# План исправления символикации

Дата: 15 октября 2026 года. Статус: реализовано в локальном рабочем дереве; [результаты проверок](2026-10-15-symbolication-repair-results.md).

Цель — восстановить работу существующего адаптера с Symbolicator 26.6.0 и подтвердить основные контракты локально и в CI. Успех определяется сохранённым результатом обработки события: ожидаемыми функцией, файлом и номером строки, корректным статусом и сохранностью исходного стека.

## Объём изменений

Сохранить существующие границы: внешний Symbolicator, приватные источники Metric, текущие хранилища debug-файлов и artifact bundles, processor и finalizer. Основные изменения сосредоточить в `crates/symbolication/src/lib.rs`, контрактных фикстурах и тестовом стенде. Application-код и callback-обработчики менять только для дефекта, воспроизведённого соответствующим тестом.

Список SDK остаётся прежним: Browser, Node.js, Python, Java, .NET, Go, Rust, PHP и Ruby. Сохраняются их закреплённые версии и существующие проверки приёма. Символикация проверяется по контрактам обработки, а не отдельной копией одного сценария для каждого SDK.

Работа не включает исправления deploy, release routes, Cron или экспорта, обновление SDK/CLI, новые мобильные стенды и массовую повторную обработку исторических событий. Приём minidump и восстановление стека из minidump — отдельный контракт; успешная обработка native-адресов не объявляется проверкой minidump.

Дополнение по запросу пользователя 15 октября: сохранить исходники вокруг восстановленных строк, добавить native source bundles и настоящий PDB, показать три вызова с кодом на localhost. Разрешена точечная миграция PostgreSQL 0022, расширяющая допустимый тип debug-файла; JSON событий и существующие данные не преобразуются. Перед дополнением исходная реализация сохранена коммитом `3f77c19`.

## Подтверждённые причины и дополнительные проверки

Отчёт `target/remote-load-200-20261015/REPORT-RU.txt` и локальные ответы настоящего контейнера показывают несовместимость wire-контракта. Существующие `sdk-tests/symbolicator/*-contract.json` и ответы в `debug_files_e2e` содержат подставные данные и не подтверждают работу настоящего backend.

Минимальные обязательные исправления адаптера:

1. Native: отправлять `stacktraces` вместо `threads`, передавать `image_size` числом и распознавать ответ `status=completed`.
2. JavaScript: отправлять `modules[].type=sourcemap`; заполнять `scraping.enabled=false`, `allowed_origins=[]`, `headers={}`.
3. Разбирать фактические признаки результата для native и JS. Наличие кадра или исходного имени функции не означает успешную символикацию. В частности, `data.symbolicated=false` не должно давать `complete`.
4. Проверить фактический response envelope и состояния выполнения обоих endpoints, сопоставление кадров с исходным стеком и диагностику отсутствующих файлов. Обрабатывать ожидаемые состояния согласно существующей политике retry/finalize; не добавлять универсальный polling без воспроизведённой необходимости.
5. Проверить native- и JS-области кэша, параметры private lookup/download и доступность callback из контейнера. Исправлять конкретные несовместимости, обнаруженные сквозными тестами.

Необходимые данные брать из настоящего ответа закреплённого контейнера. Fake backend оставить для управляемых ошибок транспорта, таймаутов и некорректного JSON; он не заменяет проверку успешной символикации.

## Локальный стенд

Один повторяемый запуск поднимает изолированные Metric, PostgreSQL, локальный BlobStore и `ghcr.io/getsentry/symbolicator:26.6.0`. Использовать существующие средства запуска сервера и подготовки БД. Зафиксировать digest реально использованного образа в результатах; fixtures и проверки должны соответствовать этой версии.

Создать только синтетические проекты, ключи, события и артефакты. Каждый прогон получает отдельные имена ресурсов, порты, БД и каталог BlobStore. Ограничить время ожидания, завершать процессы и удалять только принадлежащие прогону ресурсы, включая путь ошибки.

Заранее проверить сетевой путь Symbolicator → Metric. Если локальная топология требует доступа к зарезервированным IP, разрешение задаётся тестовой конфигурацией. Изменение production-конфигурации рассматривается отдельно только при подтверждении, что штатный приватный callback недоступен с действующими настройками.

Реальный CLI 3.x из существующего lockfile загружает debug-файл и source-map bundle через публичные API. Событие проходит публичный ingest, сохранение pending-записи, processor, запрос к Symbolicator, приватные lookup/download, finalizer и чтение через API Metric. Прямой вызов адаптера дополняет этот путь, но не заменяет его.

## Основные контракты

| Контракт | Сценарий | Обязательный результат |
| --- | --- | --- |
| Native Breakpad | Загрузить существующий `metric.sym`, отправить кадр с согласованными модулем, адресом и Debug ID | `native/complete`; функция `metric_sdk_compatibility`, файл `src/main.rs`, строка `42` из содержимого файла |
| Native ELF и DWARF | Использовать небольшой воспроизводимый Linux-бинарник с debug-информацией и заранее известной исходной строкой; загрузить соответствующий файл | Восстановление функции, файла и строки по реальному адресу; ожидаемые значения заданы независимо от ответа backend |
| Browser JavaScript | Выполнить минифицированную тестовую сборку существующим browser SDK, загрузить соответствующую map и Debug ID | Исходные функция, файл, строка и колонка совпадают с fixture; сохранены event ID и исходный минифицированный стек |
| Node.js | Отправить ошибку из собранного кода существующим Node SDK с соответствующей map | Путь `platform=node` получает правильный результат; проверка не ограничивается `platform=javascript` |
| Готовые стеки | Проверить сохранённые стеки текущих SDK и отдельные детерминированные примеры готовых кадров | Сохранены доступные функции, файлы, строки и цепочки исключений; `not_required` используется только для событий, которым преобразование не требуется |
| Сопоставление кадров | Несколько кадров и стеков: event, exception, exception raw stacktrace; смешение разрешимых и отсутствующих символов | Верны origin, индексы, порядок и связь с исходными кадрами; нет переноса символов между стеками; результат `partial` при частичном разрешении |
| Отсутствующие артефакты | Native Debug ID или JS map не загружены; JS кадр возвращён без преобразования | `missing` либо обоснованный `partial`, корректная диагностика и сохранный raw; ложный `complete` запрещён |
| Изоляция | Два проекта с одинаковыми Debug ID, но разными тестовыми символами; неверный token и чужой ID файла | Каждый проект получает свои символы; приватные endpoints не выдают чужой файл |
| Кэш и revision | Успешный холодный и повторный тёплый запрос; сначала отсутствующий файл, затем его загрузка и новое событие | Тёплый результат совпадает с холодным; новый revision устраняет устаревший negative lookup |
| Отказы backend | Управляемые timeout, 5xx, обрыв, malformed JSON, некорректная структура и превышение лимита ответа | Правильные retryable/finalize_raw и диагностика; исходный стек сохранён; сервер продолжает принимать события |

Breakpad и ELF/DWARF проверяют два основных native-сценария без добавления нового SDK. Они не означают автоматически проверенную символикацию PDB, Portable PDB или Mach-O. Для этих форматов сохраняется существующий объём поддержки; расширение подтверждённой матрицы требует собственных файлов и ожидаемых результатов.

Несколько стеков и кадров проверять без допущения, что выход всегда имеет то же число элементов, что вход. Если backend разворачивает кадры, проверить поддерживаемое сопоставление; несовместимость не маскировать перестановкой индексов или статусом `complete`.

Для перечисленных отрицательных сценариев отделять настоящий ответ Symbolicator об отсутствующих символах от искусственно созданной ошибки HTTP. В успешных сценариях fixture не должна заранее содержать ожидаемую функцию и строку вместо адреса или минифицированной позиции.

## Минимальная организация тестов

1. В `metric-symbolication` обновить небольшие тесты сериализации и разбора ответов. Сохранить управляемые транспортные тесты. Новые эталонные JSON сверить с реальным контейнером и убрать неверные старые ожидания.
2. Добавить один интеграционный target, например `crates/server/tests/symbolicator_e2e.rs`, с общими средствами подготовки проектов, загрузки артефактов и ожидания финализации. Переиспользовать код существующих стендов, избегая отдельного фреймворка.
3. Добавить один локальный координатор, например `scripts/test-symbolication.py`, для жизненного цикла инфраструктуры, выбранного backend, отчёта и очистки. Те же команды и сценарии запускать из CI.
4. Детерминированные проверки классификации и сохранности стеков поместить в существующие application/protocol/finalizer тесты. Существующие девять SDK прогнать как регрессию; не требовать внешний Symbolicator для обычного Error Event, когда он не нужен.
5. Основной полный прогон выполнить на PostgreSQL. На MongoDB повторить компактный сквозной набор native + JS и чтение финализированного события, переиспользуя текущую инфраструктуру; матрицу транспортных отказов дублировать не требуется.

## Обязательная проверка в CI и перед релизом

В `.github/workflows/ci.yml` добавить отдельный job `symbolication` на Linux. Он выполняется на PR, push в main и при вызове Checks из release workflow. Job поднимает настоящий закреплённый Symbolicator и PostgreSQL и вызывает тот же координатор, что локальный прогон.

Обязательные сценарии job: native Breakpad, native ELF/DWARF, source-map преобразование на компактном JS-событии, отсутствие символов и проверка изоляции. События могут быть детерминированными protocol fixtures: реальные Browser/Node процессы проверяются существующими SDK jobs и полным локальным прогоном. Ответы Symbolicator в этом job всегда настоящие.

У native-тестов обязательны проверки точной функции, файла и строки после финализации и чтения через Metric API. Проверка health, успешного upload, HTTP 200 или одного `status=complete` недостаточна. Зафиксировать факт приватного lookup/download на холодном кэше либо эквивалентное доказательство получения уникальных тестовых артефактов.

Отсутствующий Docker, неготовый Symbolicator, отсутствие fixture или нулевое число выполненных сценариев должны завершать job ошибкой. Запрещены `continue-on-error`, подмена backend и успешный skip. Если Rust-тесты помечены `ignored` для обычного локального cargo test, job обязан явно выбрать и выполнить их.

Ограничить время job, сохранить отчёт, версии, digest контейнера и диагностические логи при ошибке. Секреты и bearer tokens в артефакты не записывать. В шаге `always()` завершать только ресурсы данного запуска.

Проверить, что release workflow действительно ожидает успешный Checks, включая новый job, до публикации. Настройка обязательного статуса для слияния PR находится в branch rules GitHub и проверяется отдельно; наличие job в YAML само по себе её не создаёт.

## Порядок выполнения

1. Зафиксировать падающий тест с настоящим контейнером и независимыми ожидаемыми native/JS значениями. Сохранить причину сбоя и фактические ответы.
2. Исправить wire-запросы и разбор результатов. Обновить ошибочные фикстуры.
3. Пройти приватные callback и сквозную финализацию. Исправить только воспроизведённые дефекты, включая scope/revision и классификацию результатов.
4. Пройти полную локальную таблицу, существующие девять SDK и компактный MongoDB-прогон. Сохранить результаты, не включая секреты.
5. Включить обязательный CI job, проверить его выполнение и зависимость релизной публикации. Обновить `sdk-tests/README.md` командами воспроизведения и точной областью проверенной совместимости.

## Критерии завершения

- Native Breakpad и ELF/DWARF, Browser и Node source maps реально восстанавливают ожидаемые символы и позиции.
- Готовые стеки проходят без повреждения; исходные кадры остаются доступны при любом исходе символикации.
- Missing, partial и транспортные отказы различаются; отсутствие преобразования не объявляется успехом.
- Приватные источники и кэш изолированы по проектам; новые revisions не удерживают устаревшее отсутствие файла.
- Результаты прочитаны после финализации из обоих существующих backend в указанном объёме; регрессий девяти SDK нет.
- CI выполняет ненулевую native-проверку с настоящим контейнером и блокирует релиз при её сбое.
- Изменения ограничены адаптером, необходимыми точечными исправлениями по воспроизводящим тестам, проверками, фикстурами, CI и документацией. Даты, версии и результаты новых прогонов записаны в отдельный отчёт; этот план не служит свидетельством их прохождения.
