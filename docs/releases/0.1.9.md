# Metric 0.1.9

This release repairs native and JavaScript symbolication, displays resolved source
context, and adds optional retention for source-map artifact bundles.

## What's changed

- Native and JavaScript requests now match the pinned Symbolicator 26.6.0
  contract. Native inline frames and partially resolved JavaScript stacks retain
  their original frame identities.
- Event details show resolved function names, source files, line numbers and source
  snippets. A toggle restores the original frames. Oversized source context is
  omitted without discarding otherwise usable symbols.
- Native source bundles uploaded with `sentry-cli debug-files upload
  --include-sources` provide source context for PDB and DWARF debug files.
- Private artifact lookup returns the download URLs expected by Symbolicator.
  Cache scopes include project and source revisions so new uploads invalidate
  earlier misses without sharing private symbols between projects.
- Source-map uploads support sentry-cli 2.58.6 and 3.6.2 and getsentry/cli 0.44.1,
  including URL-keyed bundle entries and uncompressed chunk transport. Bundles
  retain the compression produced by the uploader.
- Chunk uploads accept an `artifact:write` token. Trusted TLS proxies preserve the
  HTTPS scheme in the advertised chunk-upload URL. sentry-cli 2.x can create a
  project release without an organization-wide project lookup.
- Cocoa object-form messages are accepted by normalization and inbound filters.
  This does not add a tested Cocoa SDK compatibility claim.
- Optional artifact retention keeps the newest bundles, recent uploads and bundles
  linked to recently active releases. Removing a binding advances source revisions;
  existing garbage collection removes unbound content after its grace period.
- TLS and DNS security fixes update `rustls` to 0.23.46, `rustls-webpki` to
  0.103.16, `webpki-roots` to 1.0.10 and `hickory-resolver` with its matching
  `hickory-net` and `hickory-proto` dependencies to 0.26.2.

## Data and upgrades

MongoDB still requires schema generation **22 exactly**. Its schema requirement
does not change from 0.1.8.

PostgreSQL now requires generation **22**. Startup applies migration
`0022_native_source_bundles.sql` to widen the debug-file type constraint for native
source bundles. Existing debug files are preserved. Once migrated, a 0.1.8 binary
cannot open this newer PostgreSQL schema. Downgrade requires restoring a matching
pre-upgrade backup of the database, BlobStore and secrets together.

Artifact retention defaults to `off`; updating does not enable deletion of old
bundles. To inspect candidates first, set `[artifacts].retention_mode = "report"`.
The defaults are `retention_max_age = "30d"`, `retention_keep_latest = 20` and
`retention_interval = "1h"`. Use `enforce` only after reviewing the reported
candidates. See [Operations](../operations.md#symbolicator).

Resolved and partially resolved stacks can produce different grouping keys after
the symbolication fixes. New events may therefore form new issues; existing events
and issues are not rewritten.

Use the matching **0.1.9** application image, Helm chart and installer assets.
Read [Update Metric](../upgrading.md) and [Backup and restore](../backup-restore.md)
before upgrading. PostgreSQL load/soak testing remains deferred; published MongoDB
performance figures do not establish PostgreSQL capacity.
